# 报告选图与档案媒体关联设计

## 目标

统一使用 `TaskPhoto` 作为任务照片、报告选图和对象档案照片墙的数据源，解决以下问题：

1. 报告编写页选择任务后，可以从该任务的全部抽帧照片或解压照片中全选或部分选择。
2. 小区、街道和重点点位档案的照片墙展示真实归档照片，不再使用前端演示数据或本地状态。
3. 图片文件只保存一份，通过关系进行查询，不在报告或档案模块复制文件。

## 业务规则

### 报告选图

- 一份综合报告属于一个任务。
- 选择任务后打开任务照片选择器。
- 默认选择状态为 `pending` 和 `archived` 的全部照片。
- `ignored` 照片可以查看，但默认不选；用户仍可手工选入报告。
- 支持全选当前任务、清空、按分发状态筛选和单张勾选。
- 分页切换不丢失已选结果。
- 确认后将所选照片载入报告标注区。
- 切换所属任务时，清空上一任务的照片、标注、描述和坐标信息，防止跨任务混用。
- 报告再次打开或编辑时，按已保存的报告照片关系恢复选择。

### 档案照片墙

- 档案照片来自 `TaskPhoto.archiveObjectId` 与当前对象档案 ID 的匹配结果。
- 一张照片最多关联一个对象档案；重新归档会替换原关联。
- “从媒体库推送”只展示 `pending` 照片，并调用现有照片分发接口完成归档。
- 归档完成后，档案照片墙和任务的待分发数量同时刷新。
- 小区、街道和重点点位共用同一套组件与接口。

## 数据模型

### 新增 ReportPhoto

```text
ReportPhoto
- id
- reportId
- taskPhotoId
- sortIndex
- createdAt
```

约束：

- `@@unique([reportId, taskPhotoId])`
- 报告删除时级联删除关系，不删除 `TaskPhoto` 或 `MediaAsset`。
- `InspectionReport.taskId` 保持唯一，继续保证一任务一份综合报告。

### 现有关系复用

- `TaskPhoto.taskId`：按任务查询照片。
- `TaskPhoto.mediaAssetId`：读取真实图片文件。
- `TaskPhoto.archiveObjectId`：按小区、街道或重点点位查询照片。
- `TaskPhoto.distributionStatus`：`pending`、`archived`、`ignored`。

## 后端接口

### 任务照片

继续使用：

```http
GET /api/v1/inspection-tasks/:taskId/photos
```

支持：

- `status`
- `page`
- `pageSize`

返回 `TaskPhoto`、`MediaAsset` 和 `archiveObject`。

### 待分发照片

新增：

```http
GET /api/v1/task-photos?status=pending&page=1&pageSize=40
```

返回照片、所属任务、来源、任务日期和媒体文件信息，用于档案页“从媒体库推送”。

### 档案照片

新增：

```http
GET /api/v1/managed-objects/:objectId/photos?page=1&pageSize=40
```

只查询 `archiveObjectId = objectId` 的真实照片，并带回所属任务信息。

### 报告照片关系

提交报告时扩展：

```http
POST /api/v1/reports
```

新增字段：

```json
{
  "taskPhotoIds": ["photo-1", "photo-2"]
}
```

后端必须校验：

- 所有照片属于 `taskId` 指定的任务。
- ID 不重复。
- 报告保存与 `ReportPhoto` 替换在同一个数据库事务中完成。

任务报告详情返回已选择的 `taskPhotoId` 列表，用于恢复编辑状态。

## 前端设计

### 报告编写页

- “所属任务”选择框继续读取真实任务列表。
- 任务选择框旁新增“选择任务照片”按钮与已选数量。
- 选择器使用弹窗，顶部提供状态筛选、全选任务、清空选择。
- 主区使用缩略图网格，每张图片显示视频时间点、文件名和归档状态。
- 默认全选 `pending + archived`。
- 确认后按视频时间点和创建时间排序载入标注区。
- 从任务详情点击单张“写报告”时，打开同一选择器并预选该照片，同时允许继续添加其他任务照片。

### 对象档案页

- `ProjectArchiveWorkspace` 不再接收 `mediaLibraryItems` 演示数据。
- 组件根据 `activeItem.id` 查询档案照片与待分发照片。
- 照片墙显示真实缩略图、任务名称、文件名、采集或视频时间点。
- “从媒体库推送”弹窗显示真实待分发照片，支持单张归档。
- 归档成功后重新请求两组列表，不维护本地 `linkedMediaIds`。

## 错误处理

- 任务无照片：选择器显示空状态，不影响报告基础信息编辑。
- 照片处理中：提示等待抽帧或解压完成。
- 照片跨任务提交：后端返回 400，报告不保存。
- 档案不存在或照片已删除：后端返回 404，前端刷新列表。
- 归档请求失败：保持弹窗和当前选择，展示服务端错误。
- 报告事务失败：报告字段和照片关系均回滚。

## 测试与验收

### 后端

- 报告只能关联所属任务的照片。
- 同一报告不会重复关联同一照片。
- 更新报告会完整替换照片选择关系。
- 档案照片接口只返回当前 `archiveObjectId` 的照片。
- 待分发接口只返回 `pending` 照片。
- 归档后待分发数量和档案照片查询同步变化。

### 前端

- 选择任务后默认全选非忽略照片。
- 全选、清空、单张选择和跨页选择均有效。
- 确认后报告标注区显示选择的真实照片。
- 切换任务不会保留上一任务照片和标注。
- 小区、街道和重点点位照片墙显示数据库中的真实照片。
- 刷新页面后档案照片仍然存在。
