# 巡检宝多项目登录与权限设计

## 目标

把当前仅服务曲阳街道的演示登录升级为可切换项目的多账号入口，并确保用户必须先选择项目，后台接口只返回当前项目的数据。

## 当前批准范围

- 删除档案页“处置时间线”，本阶段不实现该能力。
- 登录后先进入项目选择页。
- 首批项目为“曲阳街道城管巡检项目”和“金山化工园区项目”。
- 角色只有两种：管理员可查看和操作；成员只能查看，不能新增、修改或删除。
- 后端令牌保存用户角色和允许访问的项目；每个业务请求携带当前项目编号。
- 后端验证项目访问权并拦截成员的非只读请求，不能只依赖前端隐藏按钮。
- 核心业务表增加 `projectId`，列表、详情和写入均以当前项目为边界。
- 金山项目档案维度为企业、道路、河道；曲阳继续使用小区、道路、重点点位。

## 页面流程

1. 未登录访问业务页时进入 `/login`。
2. 登录成功进入 `/projects`，显示用户可访问项目。
3. 选择项目后保存当前项目并进入首页。
4. 顶部显示项目名、用户姓名和角色，并可返回项目选择页切换项目。
5. 成员账号不显示新增、编辑、删除等操作入口；即使手工调用接口，后端仍返回 403。

## 数据与接口边界

- `Project` 保存项目名称、客户类型和档案维度配置。
- 登录令牌包含用户、角色和允许访问的项目 ID，并带有效期。
- `X-Project-Id` 是受保护业务接口的必填请求头。
- 项目列表接口不要求 `X-Project-Id`，但只返回令牌允许访问的项目。
- 公开问题分享接口继续免登录，但只返回分享令牌对应的一条只读问题。
- 已有数据迁移到曲阳项目；金山项目先建立基础档案示例，不复制曲阳业务数据。

## 验收标准

- 管理员登录后可看到两个项目并正常操作。
- 成员登录后可看到两个项目，但所有非 GET/HEAD 业务请求返回 403。
- 未选择项目时不能进入业务页面。
- 选择曲阳时看不到金山档案，选择金山时看不到曲阳档案。
- 金山档案导航显示企业、道路、河道。
- 档案页不再显示处置时间线。
- 现有 API 测试、前端类型检查和构建通过。
