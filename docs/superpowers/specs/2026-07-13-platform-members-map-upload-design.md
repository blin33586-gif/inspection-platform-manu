# 平台成员管理与轻量地图上传设计

## 目标

在现有多项目隔离基础上完成两项调整：

1. 建立由唯一平台管理员维护的成员账号与项目分配体系。
2. 将项目地图管理压缩为上传和历史记录，并让 TIFF、XYZ 瓦片 ZIP 在低内存后台任务中处理，成功后自动切换当前地图。

## 已确认的权限规则

- 系统只有一个平台管理员。
- 平台管理员自动拥有全部项目访问权，并独占平台成员管理权限。
- 其他账号全部是项目成员。每个成员至少分配一个项目，只能看到被分配的项目。
- 项目成员在所属项目内拥有与平台管理员相同的业务增删改查权限，包括档案、任务、报告、问题、地图和操作日志。
- 项目成员不能访问平台成员管理接口或界面，也不能查看未分配项目。
- “更多”菜单对平台管理员和项目成员都显示。地图管理继续位于“更多”菜单中。
- “更多”入口在桌面和常用平板宽度下都不能被响应式样式隐藏；空间不足时可缩短文字或收拢项目名称，但必须保留可操作入口。
- 平台人员管理入口只对平台管理员显示，可从项目选择页和“更多”菜单进入。

## 成员账号模型

新增 `UserAccount` 和 `ProjectMembership` 数据模型。

`UserAccount` 保存：

- 姓名
- 电话
- 唯一登录账号
- 使用 Node.js `scrypt` 加随机盐生成的密码摘要
- 角色：`platform_admin` 或 `member`
- 状态：启用或停用
- 会话版本号
- 创建、更新时间和最近登录时间

`ProjectMembership` 保存成员和项目的多对多关系，成员必须至少关联一个项目。平台管理员不依赖成员关系，始终能访问全部项目。

密码永远不通过列表、详情或日志返回。新增成员时由平台管理员设置初始密码；以后只能重置密码，不能查看原密码。

## 登录与即时权限生效

- 登录由数据库账号替代当前写死的环境变量账号。
- 登录令牌只保存账号标识和会话版本，不把项目权限当作长期可信数据。
- 每次受保护请求都检查账号是否启用、会话版本是否一致，并从数据库读取当前项目关系。
- 停用账号、重置密码或调整项目分配时增加会话版本，使已有令牌立即失效。
- 平台管理员请求业务接口时可选择任意项目；成员请求必须属于当前分配项目。
- 删除现有“成员只能读取”的限制。成员在授权项目内允许 GET、POST、PATCH、PUT 和 DELETE。

## 平台管理界面

新增独立的“平台管理 / 成员账号”页面，只对平台管理员开放。

列表显示：

- 姓名
- 电话
- 登录账号
- 所属项目
- 启用状态
- 创建时间

页面操作包括：

- 新增成员
- 修改姓名和电话
- 多选成员可访问项目
- 重置密码
- 启用或停用账号

成员账号不物理删除，停用后保留历史操作记录。账号、电话和项目选择在前后端同时校验；登录账号不能重复，成员不能保存为空项目分配。

所有成员创建、资料修改、项目调整、密码重置和状态变更都记录操作日志，但日志不记录密码正文或摘要。

## 全局导航与任务页清理

- 全局导航是项目名称、账号菜单和“更多”入口的唯一来源。
- 平台管理员和项目成员始终显示“更多”菜单。成员菜单包含切换项目、地图管理和操作日志；平台管理员额外显示平台成员管理。
- 调整中等宽度响应式布局，确保约 825 像素宽的窗口仍能找到“更多”，不能只剩“退出”。
- 删除任务中心右上角没有真实功能的铃铛、固定数字 `12`、重复项目名称和假下拉箭头。
- 不为这些假控件补做功能；任务中心不再重复实现一套项目或账号菜单。
- 删除任务列表中没有实际排序交互的“按上传时间排序”装饰控件。
- 保留已有真实动作的任务搜索、日期筛选、来源筛选、状态筛选、新建任务和巡检报告入口；本阶段不扩大到删除真实业务功能。

## 地图管理界面

地图管理继续放在每个项目的“更多”菜单内，平台管理员和该项目成员都可进入。

页面只保留两个区域：

1. 地图上传：地图名称、一个文件选择框和上传按钮。支持 `.tif`、`.tiff` 和符合 `z/x/y.png` 结构的 XYZ 瓦片 `.zip`。
2. 上传历史：文件名、格式、文件大小、上传人、上传时间、处理状态、当前地图标识和失败原因。

移除页面中的流程介绍、地图类型筛选、处理状态筛选、普通图片上传、详情、下载、发布按钮和热区管理入口。旧接口可在兼容期保留，但不再出现在新页面。

地图状态统一为：

- 上传中
- 等待处理
- 处理中
- 当前使用
- 处理失败

## 轻量地图处理流程

### 上传阶段

- API 使用磁盘存储接收 multipart 文件，上传内容不进入 Node.js 大型内存 Buffer。
- 文件完成落盘后创建地图历史记录和后台任务，接口立即返回。
- TIFF 和 ZIP 都通过统一上传入口登记，实际处理不占用 API 请求线程。

### 后台阶段

- 地图处理队列全局并发数固定为 1，避免多个大地图同时抢占 CPU 和内存。
- TIFF 交给独立 GDAL 子进程分批生成 XYZ 瓦片，并限制 GDAL 缓存和工作内存。
- ZIP 先通过中央目录检查路径、格式、重复坐标和穿越路径，再由系统解压程序流式写入独立瓦片目录；应用进程不读取全部瓦片内容。
- 处理中的临时目录与正式目录分离。失败时删除临时文件和不完整瓦片，保留错误原因。

### 自动切换

- 处理期间继续使用原当前地图。
- 新地图完整处理并通过结构校验后，在数据库事务中将其设为当前地图，并取消旧地图的当前标识。
- 任何失败都不能影响旧地图。
- 同一项目连续上传多个文件时按任务创建顺序处理；每个成功任务处理完成时成为该项目当前地图。

### 浏览器加载

- 地图页只请求当前视野和缩放级别需要的瓦片。
- 瓦片响应保留长期缓存头，避免重复读取。
- 不在浏览器端加载整张 TIFF 或整个 ZIP。

## 数据与接口边界

平台接口位于项目上下文之外，并且只允许平台管理员调用：

- 读取成员列表
- 新增成员
- 编辑成员资料和项目
- 重置密码
- 启用或停用成员

项目列表接口根据数据库权限返回：平台管理员返回全部项目，成员只返回已分配项目。

地图上传、历史记录和瓦片读取继续使用当前项目上下文，所有查询和写入都必须包含项目条件。地图历史补充上传人、失败原因和激活时间字段。

## 迁移策略

- 将现有 `admin` 账号迁移为唯一平台管理员。
- 将现有 `member` 账号迁移为普通项目成员，并保留当前两个项目作为初始分配，之后可在平台管理中调整。
- 迁移只建立账号和关系，不修改现有项目业务数据和地图文件。
- 原环境变量密码只用于首次初始化或紧急恢复，不再作为日常成员账号来源。

## 异常处理

- 重复账号、无项目成员、无效电话和弱密码返回明确的表单错误。
- 停用账号登录返回统一的账号不可用提示，不泄露账号是否存在。
- 成员访问未分配项目或平台接口返回 403。
- 文件格式、瓦片目录、磁盘空间或 GDAL 处理失败时，历史记录进入“处理失败”并保存可读原因。
- 失败上传清理临时数据；旧地图继续服务。

## 测试与验收

- 平台管理员能看到全部项目和平台成员管理。
- 成员只看到分配项目，不能访问平台管理或未分配项目。
- 平台管理员和成员在约 825 像素宽窗口中都能看到并打开“更多”菜单。
- 任务中心不再显示铃铛、固定通知数字、重复项目名称或假下拉菜单。
- 任务列表不再显示不能操作的“按上传时间排序”装饰控件。
- 成员在所属项目内可以新增、修改和删除业务数据。
- 调整项目、停用账号或重置密码后，旧登录令牌立即失效。
- 成员列表和接口不返回密码或密码摘要。
- TIFF 和 ZIP 上传会立即进入历史记录，后台串行处理。
- 新地图成功后自动成为当前项目地图；失败任务不改变旧地图。
- 大文件处理过程中 API 与管理端不出现随文件大小等比例增长的内存占用。
- 地图页面按视野请求瓦片并命中浏览器缓存。
- 账号、权限、项目隔离、地图处理、迁移、API 类型检查、前端构建和浏览器主流程均通过验证。

## 本阶段不做

- 多个平台管理员
- 自助注册和找回密码
- 项目内细粒度角色或按模块授权
- 外部对象存储、GeoServer 或云地图服务
- 地图版本手工发布和历史回滚
- 在地图管理页恢复热区编辑等高级工具
