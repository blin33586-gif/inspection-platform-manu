# 问题基础信息编辑与同步设计

## 目标

让问题详情页的基础信息成为真实可用的编辑入口，并确保问题详情、问题库上级卡片及其他读取该问题的界面始终使用同一份数据。

## 编辑入口与交互

- 问题详情概览区增加“编辑信息”入口，点击后将四项信息切换为统一表单。
- 表单一次编辑并保存关联对象、问题类型、严重程度和发现时间，提供明确的“保存”和“取消”。
- 保存成功后刷新详情数据；返回问题库时，上级问题卡片读取相同记录并显示新值，不维护第二份展示数据。
- 问题卡 PNG 是数据库记录的派生展示；问题类型或发现时间变化后同步重新生成，并使用数据版本参数避免浏览器继续显示旧图。
- 已闭环、暂不处理和已归档问题仍允许校正基础信息；编辑不会改变问题状态、闭环时间或整改记录。
- 保存失败时保留用户当前输入并显示错误，不展示未写入数据库的假成功状态。

## 字段规则

- 关联对象：从当前项目的档案对象中选择，也允许清除为“未关联对象”；不得关联其他项目档案。
- 问题类型：必填文本，去除首尾空白，最多 100 个字符。
- 严重程度：界面仅显示“严重 / 重要 / 轻微”，分别对应现有数据值 `high / medium / normal`，不改动数据库枚举，避免破坏历史数据。
- 发现时间：允许人工修改日期和具体时间，用于校正照片上传时间与实际事件发生时间的偏差；保存为标准时间值，并按中国本地时间编辑和展示。

## 数据与权限

- 新增项目范围内的问题基础信息更新接口，接受 `objectId`、`category`、`severity`、`foundAt` 四个字段。
- 接口按当前登录身份和当前项目校验问题及关联档案；项目成员与平台管理员沿用现有项目写权限。
- 更新关联对象时，同一事务内同步维护原、新档案的问题数量，防止统计失真。
- 更新成功后写入操作日志，记录操作者、问题编号和发生变化的字段；日志不记录无变化的重复保存。
- 问题详情和问题库卡片继续通过同一问题记录查询，不新增前端本地副本或独立同步表。
- 只有具备原始照片和标注版本的问题才重新生成问题卡；没有问题卡的人工问题正常保存基础信息，不凭空生成图片。

## 页面范围

- 本次只在问题详情页提供编辑入口；问题库上级卡片负责同步显示最新值，不额外增加第二套编辑表单。
- 保持现有紧凑概览版式和整改闭环工作区，不重做已确认的整改记录、附件及闭环流程。
- 在窄屏下表单保持单列，按钮可点击且不横向溢出。

## 验收标准

- 可在详情页选择当前项目档案、修改问题类型、选择“严重 / 重要 / 轻微”并校正发现时间。
- 清除关联对象后正确显示“未关联对象”，选择其他项目档案时后端拒绝。
- 保存后详情立即更新，返回问题库后上级卡片显示完全一致的新数据。
- 已闭环问题可修改上述四项信息，但状态仍为“已闭环”，原整改记录保持不变。
- 修改关联对象后原、新档案的问题数量正确；有效修改产生操作日志。
- 刷新页面、重新登录后数据仍保持，错误请求不会造成部分更新。
