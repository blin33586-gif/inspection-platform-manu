# 统一任务媒体库与素材预览设计

日期：2026-07-11  
状态：已确认方案 A，等待书面规格复核

## 1. 目标

把当前以视频为中心的媒体库升级为统一任务入口。一项任务可以来自 MP4/MOV 视频，也可以来自包含巡检照片的 ZIP。视频完成离线抽帧后、ZIP 完成安全解压后，都在同一个任务下展示可查看、可选择、可进入报告编写的图片素材。

本模块同时完成三项界面调整：

- “视频任务”统一改为“任务”，统计使用“任务数”。
- 视频任务缩略图支持鼠标悬停静音播放预览，离开后停止并复位；触屏设备保留播放按钮。
- 选中任务后，在任务列表下方显示该任务的素材预览网格。

## 2. 范围

### 2.1 本期实现

- 上传 MP4、MOV 和 ZIP。
- MP4/MOV 上传后创建 `frame_extract` 任务，由 FFmpeg 按指定间隔抽帧。
- ZIP 仅提取 JPG、JPEG、PNG，忽略 ZIP 内目录层级，统一平铺为一个图片任务。
- 后台任务状态统一为待处理、处理中、已完成、失败。
- 视频原文件支持 HTTP Range 读取，供缩略图悬停预览和播放按钮使用。
- 视频抽帧图片及 ZIP 解压图片以子媒体资产形式回写媒体库。
- 点击素材图片进入报告编写页，并自动带入当前图片。
- 失败任务显示可理解的错误原因并支持重试。

### 2.2 本期不实现

- 不在 ZIP 解压阶段执行 AI 识别。
- 不保留 ZIP 内部目录树。
- 不支持 RAR、7z、HEIC、RAW 或视频压缩包。
- 不实现多张照片一次性加入报告；第一版按单张图片进入报告编写页。
- 不改变现有照片标注工具、报告提交和报告管理逻辑。

## 3. 用户体验

### 3.1 上传入口

顶部按钮名称改为“上传素材”，文件选择器接受 `.mp4`、`.mov`、`.zip`。选中后按文件类型自动进入对应处理流程，不要求用户先选择“视频”或“图片包”。

视频沿用 2 至 5 秒的抽帧间隔设置；ZIP 不使用该设置。上传完成后自动选中新任务。

### 3.2 任务列表

任务卡片统一显示：来源、处理状态、任务名称、原始文件名、关联项目、素材数量和处理进度。视频额外显示抽帧间隔；图片包显示“图片包”和解压图片数量。

视频任务缩略图默认显示首张抽帧图片。鼠标进入缩略图时加载原视频并静音播放，鼠标离开时暂停并回到开头。只有当前悬停的一张卡片加载视频，避免列表同时下载多个大文件。视频不可播放时继续显示首帧图片，不影响任务操作。

### 3.3 素材预览

选中已完成任务后，在任务列表下方出现“素材预览”：

- 视频任务按视频时间顺序展示抽帧照片，并显示时间点。
- 图片包按解压顺序展示全部照片，并显示文件名。
- 点击照片打开大图预览。
- 每张照片提供“写报告”操作，进入 `/reports/write?mediaId=<图片ID>`。
- 处理中任务显示进度；失败任务显示原因和重试；没有素材时显示明确空状态。

右侧现有“疑似问题事件”区域继续保留，后续 AI 识别结果仍与当前选中任务关联。

## 4. 数据与服务边界

### 4.1 媒体资产

继续复用 `MediaAsset` 的父子关系，不新增平行媒体表：

| kind | 含义 | 父资产 |
| --- | --- | --- |
| `video` | 上传的 MP4/MOV 原文件，也是视频任务主体 | 无 |
| `image_bundle` | 上传的 ZIP 原文件，也是图片任务主体 | 无 |
| `frame` | FFmpeg 从视频抽出的 JPEG | 对应 `video` |
| `image` | ZIP 解压出的 JPG/JPEG/PNG | 对应 `image_bundle` |

任务列表以顶层资产为任务，素材预览读取其子资产。文件显示名使用原始文件名；存储名使用平台生成的唯一名称，避免重名覆盖。

### 4.2 处理任务

继续复用 `MediaProcessingJob`：

- `frame_extract`：视频抽帧。
- `archive_extract`：ZIP 图片安全解压。

两个任务使用相同的领取、进度、错误和重试规则。任务完成时写入素材数量和输出目录，并记录操作日志。

### 4.3 文件访问

API 提供受保护的媒体内容接口，支持视频 Range 请求和图片直接读取。前端使用现有登录令牌生成媒体地址，不公开服务器真实存储路径。

## 5. API 设计

- `POST /media-assets/upload`：统一上传视频或 ZIP，自动识别类型并创建对应后台任务。
- `GET /media-assets/tasks`：返回顶层媒体任务及最新处理任务摘要。
- `GET /media-assets/:id/children`：返回视频帧或解压图片列表。
- `GET /media-assets/:id/content`：读取视频或图片内容；视频支持 `Range`。
- `POST /media-jobs/:id/retry`：重试失败的 `frame_extract` 或 `archive_extract` 任务。

旧的 `GET /media-assets/videos` 在前端切换完成后保留一个版本周期，随后删除，避免新旧界面切换期间中断。

## 6. ZIP 安全规则

ZIP 解压由媒体工作进程执行，不在 API 请求内同步解压。第一版默认限制：

- 压缩文件最大 2 GB。
- 最多提取 1000 张图片。
- 解压后总大小最大 8 GB。
- 单张图片最大 50 MB。
- 仅接受扩展名和文件签名均为 JPG/JPEG/PNG 的文件。
- 拒绝绝对路径、`..` 路径穿越、符号链接和加密 ZIP。
- 拒绝空图片包；存在非图片文件时忽略并在任务结果中记录数量。
- 同名图片自动追加序号，避免覆盖。

限制值后续可改为环境变量，但第一版不提供界面配置。

## 7. 报告编写衔接

报告编写页读取查询参数 `mediaId`，调用媒体元数据和内容接口，把该图片作为当前报告第一张照片。图片仍使用现有矩形、箭头、文字、移动和说明暂存功能。

如果媒体不存在、无权限或文件损坏，报告页显示“素材读取失败”，保留手工上传入口，不让整个报告页面崩溃。

本期只传入图片，不自动创建问题、不自动提交报告，也不改变报告归档规则。

## 8. 错误与恢复

- 文件类型不支持：上传接口返回明确的 400 错误。
- ZIP 损坏或违反安全规则：后台任务标记失败，任务卡片显示原因。
- FFmpeg 或解压过程失败：保留原始上传文件，允许重试，不重复创建顶层任务。
- 部分图片损坏：跳过损坏图片；只要至少有一张有效图片，任务完成并记录跳过数量。
- 页面轮询失败：保留最后一次成功数据，并显示可重试提示。
- 视频预览失败：退回首帧静态图，不影响抽帧素材和报告入口。

## 9. 测试与验收

### 9.1 自动测试

- API：视频、ZIP、非法格式、任务列表、子素材、Range 响应和重试。
- 工作进程：ZIP 路径穿越、文件签名、数量/大小限制、同名文件、损坏图片和正常解压。
- 前端：统一任务映射、视频悬停状态、素材网格、空/失败状态和报告链接参数。
- 回归：现有视频抽帧、TIF 瓦片、报告编写和登录鉴权测试保持通过。

### 9.2 浏览器验收

1. 上传 MP4，任务进入处理并最终展示抽帧照片。
2. 鼠标移入视频缩略图可静音播放，移出后停止。
3. 上传含子目录的 ZIP，全部有效图片在一个任务中平铺显示。
4. 点击任意抽帧或解压图片的“写报告”，报告页显示该图片并可标注。
5. 上传非法 ZIP 时任务失败且原因可见，重试按钮行为正确。
6. 桌面和窄屏下任务卡片、素材网格和右侧事件区不重叠。

## 10. 完成标准

统一任务媒体库必须形成“上传素材 → 后台处理 → 查看素材 → 进入报告”的可用闭环。只有任务名称改动或静态示例预览不算完成；后端存储关系、实际文件读取、ZIP 解压、视频 Range 预览和报告图片传递均需通过真实文件验收。
