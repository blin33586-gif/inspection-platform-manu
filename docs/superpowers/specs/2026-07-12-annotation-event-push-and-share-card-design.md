# 图片标注事件推送与分享卡设计

## 目标

在现有“报告编写／图片标注”页增加“事件推送”入口。巡检人员对当前照片完成标注后，只填写必要的业务字段，一次提交同时：

1. 在问题台账中创建一条“待处理”问题。
2. 保存当前标注照片与具体标注版本的证据关系。
3. 创建无需登录的只读分享页。
4. 生成指向该分享页的二维码。
5. 生成并保存 70% 照片占比的 PNG 业务卡。
6. 向页面返回卡片预览、PNG 下载、分享链接和内部问题详情入口。

## 已有能力与依赖

- `TaskPhoto` 是任务照片唯一实体，不复制原始媒体文件。
- `PhotoAnnotationDocument` 保存当前标注、问题描述、经纬度和当前版本。
- `PhotoAnnotationVersion` 保存不可修改的历史标注。
- `Issue` 和问题台账页已存在，新问题默认使用 `pending` 状态。
- 报告编写页已能根据经纬度构造腾讯地图定位链接。

本功能在这些已定型能力上追加，不重做标注编辑器、媒体存储或问题台账列表。

## 用户流程

1. 用户在报告编写页选中一张任务照片。
2. 用户完成矩形、箭头或文字标注，并先保存当前标注版本。
3. 用户点击“事件推送”。
4. 弹窗自动带入已知内容，并要求确认：
   - 点位／区域
   - 发现时间
   - 问题类型
   - 问题描述
5. 前端提交一次“事件推送”请求。
6. 后端完成问题创建、证据固化、分享链接、二维码和 PNG 卡片生成。
7. 前端展示结果弹窗，提供“下载 PNG”“复制分享链接”“打开问题详情”。

## 模块与接口

### 事件推送模块

外部只暴露一个小接口：

```http
POST /api/v1/task-photos/:photoId/publish-issue
```

请求体：

```json
{
  "expectedAnnotationVersion": 4,
  "locationName": "广灵二路小区北门",
  "foundAt": "2026-07-12T11:06:00+08:00",
  "category": "暴露垃圾",
  "description": "垃圾桶周边散落生活垃圾，地面有污渍。"
}
```

返回：

```json
{
  "issueId": "issue-...",
  "shareUrl": "https://.../s/issue/...",
  "cardImageUrl": "/api/v1/issues/.../share-card.png",
  "issueDetailUrl": "/issues/..."
}
```

调用者无需知道事务顺序、令牌生成、二维码编码、图片合成和文件存储细节。

### 只读分享模块

```http
GET /api/v1/public/issues/:shareToken
GET /api/v1/public/issues/:shareToken/card.png
```

- `shareToken` 必须由密码安全的随机数生成，不得使用自增 ID 或可猜测的问题编号。
- 分享页无需登录，但仅显示本条问题的只读内容。
- 分享页不返回其他问题、管理员信息、审计记录、内部存储路径或编辑接口。
- 分享页提供“地图定位”和“开始导航”，使用证据中固化的经纬度。
- 后台可撤销分享；撤销后令牌立即失效，不影响内部问题记录。

## 数据模型

在 `Issue` 上补足事件证据与分享所需数据：

```text
Issue
- description                 // 问题描述
- locationName                // 点位／区域文本快照
- sourceTaskPhotoId           // 当次推送的照片
- sourceAnnotationVersion     // 推送时的不可变标注版本
- longitude
- latitude
- shareTokenHash              // 数据库不保存可直接使用的明文令牌
- shareEnabled
- cardStoragePath
- cardMimeType
- cardFileSize
- publishedAt
```

`sourceTaskPhotoId + sourceAnnotationVersion` 是问题卡的证据基线。后续继续编辑当前照片标注时，已推送的问题卡不自动改变。

## 业务卡生成

第一版由后端统一生成 PNG，避免浏览器、字体和设备差异导致版式不一致。

卡片固定规则：

- 整体为稳重蓝色业务卡牌风格。
- 标注后的现场照片约占卡片高度的 70%。
- 底部左侧依次呈现点位／区域、发现时间、问题类型和问题描述。
- 底部右下角呈现指向公开只读详情页的二维码。
- 二维码下方使用“扫码查看问题详情”。
- 输出必须对中文、超长点位名称和多行问题描述做截断或折行保护，不得与二维码重叠。
- 卡片作为问题的固化证据产物，默认不因后续状态改动而自动重绘。

## 事务、幂等与失败处理

- 每次提交带有幂等键，页面重试不得创建重复问题。
- 创建问题、固化证据版本和创建分享令牌在同一数据库事务中完成。
- PNG 生成失败时，问题保留为已创建，记录“卡片生成失败”并允许后台重试，不重复创建问题。
- 当前标注未保存或 `expectedAnnotationVersion` 不匹配时，返回 `409`，不创建问题。
- 当前照片缺少问题描述时，前后端均拒绝推送。
- 缺少经纬度时允许创建问题与卡片，但只读页的地图按钮显示“暂无定位”并禁用。
- 分享令牌不存在或已撤销时，公开详情页返回统一的“分享已失效”页面。

## 安全与审计

- 公开分享端点只接受令牌，不接受内部 `issueId` 替代令牌。
- 卡片 PNG 和公开证据图片通过受控读取接口返回，不直接暴露存储路径。
- 按令牌查询需有索引，并对公开端点配置请求速率限制。
- 事件推送、卡片生成失败／重试、分享撤销均写入操作审计。
- 公开页不显示操作者姓名、内部存储信息或管理操作。

## 页面改动

### 报告编写页

- 在当前照片的问题描述区附近增加“事件推送”按钮。
- 未选择真实 `TaskPhoto`、标注存在未保存改动、或问题描述为空时，按钮禁用并显示原因。
- 弹窗自动带入任务、照片、标注版本、坐标、发现时间和问题描述。
- 用户只确认点位／区域、发现时间、问题类型和问题描述。
- 提交成功后展示卡片预览和三个动作：下载 PNG、复制分享链接、打开问题详情。

### 公开只读问题页

- 新增 `/s/issue/:shareToken` 路由，不进入后台登录守卫。
- 展示标注后照片、点位／区域、发现时间、问题类型和问题描述。
- 有经纬度时提供“地图定位”和“开始导航”。
- 页面只读，不展示状态修改、附件上传或后台导航。

## 验收标准

1. 用户可从一张已保存标注的任务照片发起事件推送。
2. 一次提交创建且只创建一条 `pending` 问题。
3. 问题引用提交时的具体标注版本，后续标注修改不改变已发布证据。
4. 生成的 PNG 符合 70% 照片占比、左侧业务信息和右下角二维码的已确认版式。
5. 系统保存卡片，并可在提交结果中预览与下载 PNG。
6. 扫描二维码无需登录即可查看本条问题的只读详情。
7. 只读页不泄露其他问题、存储路径或后台管理能力。
8. 只读页在有坐标时能打开腾讯地图定位与导航。
9. 重复提交相同幂等键时返回已有结果，不生成重复问题。
10. 公开分享可在后台撤销，撤销后链接立即失效。

## 实施边界

本模块只实现“单张已标注照片→问题台账＋分享卡”。不在本模块实现 AI 自动识别、连续帧事件合并、多照片事件、整份日报自动排版或整改前后自动匹配。
