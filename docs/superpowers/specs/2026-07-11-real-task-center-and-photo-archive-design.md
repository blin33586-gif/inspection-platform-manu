# 真实任务中心与照片归档设计

## 目标

- 将当前“视频巡检分析中心”收敛为真实的“巡检任务中心”。
- 视频、ZIP、单张或多张图片统一进入任务；视频抽帧是视频任务的必做处理。
- 任务只描述接入批次、来源和处理状态，不直接关联小区、道路或重点点位。
- 照片是分拣、标注、问题证据和档案归属的最小业务单位。
- 一张照片最多归档到一个对象，同时保留任务与档案两个查询维度。
- 一个任务最终对应一份综合巡检报告。

## 统一业务流程

```text
新建任务
  -> 选择来源和任务日期
  -> 上传视频 / ZIP / 单张或多张图片
  -> 视频必须抽帧，ZIP 必须解压，图片直接入池
  -> 形成任务照片池
  -> 照片标注、AI识别或人工复核
  -> 每张照片选择：已归档 / 无需归档
  -> 已归档照片唯一关联小区、道路或重点点位
  -> 任务全部照片处理完成
  -> 生成一份综合巡检报告
```

## 术语与边界

### 任务

- 任务是一次素材接入和处理批次。
- 任务不关联档案对象。
- 任务记录名称、任务日期、来源、输入类型、处理状态、照片数量和综合报告。
- 任务来源固定为：
  - `manual`：人工上传。
  - `drone`：无人机。
  - `camera`：摄像头自动拉取。
  - `glasses`：AI 眼镜。
- 新建任务时来源必选，默认人工上传；后续自动接入服务在创建任务时写入对应来源。

### 输入类型

- `video`：一个 MP4 或 MOV，必须创建 FFmpeg 抽帧任务。
- `archive`：一个 ZIP，只接收 JPG、JPEG、PNG，必须安全解压。
- `images`：一张或多张 JPG、JPEG、PNG，直接写入任务照片池。
- 同一个任务不混合视频、ZIP 和直接图片三种输入类型。

### 任务照片

- 视频帧、ZIP 解压图片和直接上传图片最终都成为任务照片。
- 原视频和 ZIP 原文件继续保留用于追溯，但不直接进入档案和报告证据。
- 照片分发状态：
  - `pending`：待分发。
  - `archived`：已归档到一个对象。
  - `ignored`：无需归档。
- 一张照片不能同时关联多个档案。
- 重新归档允许修改唯一归属，但必须写入归档历史和操作日志。

## 数据模型

### InspectionTask

- `id`
- `name`
- `taskDate`
- `sourceType`
- `inputType`
- `processStatus`
- `sourceMediaId`
- `photoCount`
- `pendingPhotoCount`
- `createdAt`
- `updatedAt`

`sourceMediaId` 指向原始视频或 ZIP；直接图片任务可以为空。

### TaskPhoto

- `id`
- `taskId`
- `mediaAssetId`
- `distributionStatus`
- `archiveObjectId`
- `capturedAt`
- `videoTimestampMs`
- `createdAt`
- `updatedAt`

约束：

- `mediaAssetId` 唯一。
- `distributionStatus = archived` 时 `archiveObjectId` 必须存在。
- `distributionStatus = pending/ignored` 时 `archiveObjectId` 为空。
- `archiveObjectId` 只允许指向小区、道路或重点点位。

### PhotoArchiveHistory

- `id`
- `taskPhotoId`
- `fromObjectId`
- `toObjectId`
- `action`
- `actor`
- `createdAt`

记录首次归档、重新归档、取消归档和标记无需归档。

### 报告与问题关系

- `InspectionReport` 新增可空 `taskId`，新任务生成报告时必须填写。
- `taskId` 唯一，保证一个任务只有一份综合报告。
- 新增 `ReportPhoto`，记录报告使用的任务照片。
- 新增 `IssueEvidence`，记录问题与任务照片的证据关系。
- 问题继续保留唯一 `objectId`，其档案归属与证据照片归属保持一致。

## 两个查询维度

### 按档案查询

```text
小区 / 道路 / 重点点位
  -> archiveObjectId 对应的 TaskPhoto
  -> 照片标注和问题
  -> 照片所属任务
  -> 任务综合报告
```

档案页只展示真实归档照片，不复制媒体文件。

### 按日期或任务查询

```text
任务日期范围
  -> InspectionTask
  -> 任务照片池
  -> 每张照片的分发状态和唯一档案
  -> 问题事件
  -> 一份综合巡检报告
```

## 任务中心页面

### 标题与真实数据

- 页面名称改为“巡检任务中心”。
- 删除演示任务、演示事件和由前端数组计算的假统计。
- 页面只展示数据库中的 `InspectionTask`。
- 统计卡改为：
  - 任务总数。
  - 正在处理任务数。
  - 待分发照片数。
  - 已生成报告数。
- 统计随筛选条件实时从 API 返回，不从前端假数据推导。

### 真实筛选

- “上传日期”假按钮改为日期范围选择器，筛选字段使用任务创建时间。
- 支持任务日期、关键字、来源、处理状态筛选。
- 筛选参数由 API 执行，并返回筛选后的统计和任务列表。
- 来源和状态不再混用；来源仅显示人工、无人机、摄像头、AI 眼镜。

### 新建任务

- “上传素材”改为“新建任务”。
- 打开任务表单：
  - 任务名称。
  - 任务日期。
  - 来源。
  - 输入类型。
  - 文件选择。
  - 视频抽帧间隔 1 至 5 秒，默认 3 秒。
- 文件规则：
  - 视频：只能选择一个 MP4/MOV。
  - ZIP：只能选择一个 ZIP。
  - 图片：允许选择一张或多张 JPG/JPEG/PNG。
- 提交后创建任务和处理工作，跳转到任务详情页。

### 任务卡

- 显示真实任务名称、来源、任务日期、输入类型、处理状态、照片数量和待分发数量。
- 不显示“待关联项目”，因为任务不关联档案。
- 点击进入 `/media-library/:taskId`。

## 任务详情与照片分发

- 详情页保留原始视频播放和照片池。
- 照片支持单选和批量选择。
- 分发动作打开档案选择器，按“小区、道路、重点点位”分组搜索。
- 一次批量分发可以把多张照片归档到同一个对象。
- 已归档照片再次分发时，界面明确提示将修改原归属。
- “无需归档”支持单张和批量处理。
- 照片卡显示分发状态和当前档案名称。
- 任务完成条件：后台素材处理完成，且照片不存在 `pending` 状态。

## 报告规则

- 一个任务只生成一份综合巡检报告。
- 报告可以引用任务中多个不同档案的照片。
- 每个报告问题必须显示照片、问题类型、档案归属、发现时间、标注信息和处理建议。
- 从档案照片可以反向进入任务和综合报告。
- 未归档照片不能作为正式问题证据加入报告；`ignored` 照片不进入报告。

## API 边界

- `POST /inspection-tasks`：新建并上传任务。
- `GET /inspection-tasks`：服务端筛选任务和真实统计。
- `GET /inspection-tasks/:id`：任务详情和处理摘要。
- `GET /inspection-tasks/:id/photos`：任务照片分页列表。
- `PATCH /task-photos/distribute`：单张或批量归档到唯一对象。
- `PATCH /task-photos/ignore`：标记无需归档。
- `GET /managed-objects/options`：档案选择器数据。
- 原有 `/media-assets` 和 `/media-jobs` 继续作为底层媒体存储与技术处理接口，不直接暴露为业务任务概念。

## 错误与一致性

- 任务创建和素材资产创建使用数据库事务；文件处理失败时任务显示失败并可重试。
- 分发时校验照片属于目标任务、目标对象存在且类型合法。
- 批量分发使用事务，任一照片失败则整批不更新。
- 归档、重新归档、忽略和取消忽略均写入操作日志。
- 数据库迁移不删除现有媒体；现有顶级视频和 ZIP 转换为历史任务，子媒体转换为任务照片。

## 分阶段实施

### 阶段 1：真实任务底座

- 新增任务和任务照片数据表。
- 迁移现有媒体数据。
- 新建任务支持视频、ZIP、单张和多张图片。
- 真实日期筛选、来源筛选、状态筛选和统计。
- 删除媒体库演示任务、假事件和假统计。

### 阶段 2：照片分发归档

- 新增照片唯一档案关系和归档历史。
- 详情页提供单选、批量分发和无需归档。
- 档案页展示真实归档照片，并可返回任务。

### 阶段 3：问题与综合报告

- 建立问题证据、报告照片和任务报告关系。
- 一个任务生成一份综合报告。
- 实现按档案和按日期/任务的双向查询。

## 验收标准

- 页面不存在上传日期假按钮、演示任务或假统计。
- 视频、ZIP、单张图片和多张图片都能创建任务。
- 视频任务必须完成抽帧后产生任务照片。
- 日期、来源和状态筛选由真实 API 返回结果。
- 统计与数据库记录一致。
- 任务卡只显示来源，不显示任务级档案关联。
- 每张照片最多关联一个档案。
- 所有照片完成归档或忽略后，任务可标记完成。
- 档案和任务两个入口均能找到同一张照片、问题和综合报告。
- 一个任务不能创建第二份综合报告。
