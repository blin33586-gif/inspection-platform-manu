# 档案、问题库与报告闭环设计

## 目标

完成三个相互独立、通过现有数据关系连接的模块：档案删除审批、PNG 问题库、HTML 报告成册。

## 档案删除审批

- 档案页删除按钮只创建一条待确认操作日志，不直接删除数据库记录。
- 操作日志显示“确认删除”和“取消申请”。
- 确认删除时，问题、报告和地图热区保留但解除对象关联；照片解除归档并回到任务库待分发；最后删除档案。
- 同一档案同时只能存在一条待确认删除申请。

## 照片墙

- 标题统一为“照片墙”。
- 移除状态筛选、来源说明和媒体库推送入口。
- 每张照片提供删除按钮；删除只解除与当前档案的关联，原照片回到任务库待分发。

## PNG 问题库

- 问题库只展示已经生成 PNG 问题卡的问题。
- 以问题卡图片为主要内容，保留关键词和状态筛选。
- 页面状态只呈现“待处理”和“已处理”；历史状态统一映射到这两个展示状态。
- 操作只保留状态切换和详情。

## HTML 报告成册

- 提交报告成功后进入报告详情页，不返回空白列表页。
- 报告详情按 A4 纸张样式逐张展示所选照片对应的问题卡；没有问题卡时回退显示原照片。
- 每页显示序号、照片、问题说明、点位和时间。
- 支持浏览器打印和另存 PDF；服务端 PDF 导出留作后续模块。

## 验收

- 档案删除申请能在操作日志确认或取消，确认后档案消失且照片回到待分发。
- 照片墙删除不物理删除原图。
- 问题库不再出现处理中、复查通过等旧操作。
- 提交报告后立即看到可打印的逐页报告内容。
